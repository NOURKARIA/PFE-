Ultra-Detailed Project Report: IA Test Agent

This report provides an in-depth analysis of the IA Test Agent project, including its workflow, implemented files, contents, and current deliverables.

Project Overview

The IA Test Agent is an AI-driven test automation platform that combines Natural Language Processing (NLP), Computer Vision, and Playwright browser automation. It translates Gherkin-style test steps into executable browser actions, detects UI elements from screenshots, and performs retries and vision fallback for robust execution.

Detailed Workflow

1. Input Processing (NLP Parsing)

  • User submits Gherkin text via API endpoint /api/ia/parse-gherkin.
  • app/services/nlp_service.py parses the text with app/utils/gherkin_parser.py and extracts scenarios and steps.
  • nlp/entity_extractor.py extracts values and identifiers, while nlp/intent_classifier.py classifies step intent.
  • Mapped actions are built into structured payloads for execution.

2. Semantic Mapping

  • app/services/mapping_service.py maps NLP intents to Playwright methods such as click, input, navigate, and assert.
  • Current logic generates text selectors from the detected target text and stores metadata for debugging.

3. UI Element Detection (Vision)

  • User provides an image URL or local path via /api/ia/detect-ui.
  • app/services/vision_service.py uses YOLOv8 to detect UI elements and returns bounding boxes, labels, confidence scores, and center coordinates.
  • Detected UI patches are also processed with OCR, and text similarity is used to match targets.

4. Test Generation

  • app/services/generator_service.py converts mapped NLP actions into Playwright operations.
  • It supports navigation, click, input, wait, select, and assertion actions based on available selectors or coordinates.

5. Test Execution

  • app/services/executor_service.py manages Playwright sessions, dialog handling, and page lifecycle.
  • Endpoint /api/ia/execute-test executes single Gherkin steps and returns detailed result payloads.
  • Execution includes retry logic, a vision fallback path, and screenshot capture for each executed step.

6. Reporting

  • HTML report template is present at app/templates/report.html.j2.
  • app/services/report_service.py and the related reporting API are currently placeholders awaiting integration.

Architecture and Dependencies

The system is built with:

  • Backend: FastAPI with Pydantic for API development
  • NLP: spaCy for entity extraction, HuggingFace transformers for intent classification
  • Vision: Ultralytics YOLOv8 for object detection, OpenCV for image processing
  • Automation: Playwright for browser automation
  • Reporting: Jinja2 templates for HTML generation
  • Testing: pytest for unit testing
